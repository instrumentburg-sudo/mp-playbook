# Инструмент «Конвейер новинок» — дизайн-драфт (23.04.2026)

Это **текстовый план** (не код). Обсуждаем здесь, потом генерируем артефакт.

## 1. Что мы пытаемся решить

Из слов Антона: «реальная проблема — аналитика и вывод новых товаров». Курс даёт методологию, но курс = знание, а нам нужен **инструмент** — повторяемый процесс, который:
1. Не даст пропустить этап (семантика, юнит-экономика, сертификат).
2. Хранит состояние каждого SKU (от идеи до продажи).
3. Считает по свежим комиссиям (Ozon апр'26!), не по курсу.
4. Встраивается в существующий стек ИнструментБург (паттерны `avito-feed-pipeline`, `pipeline-state.md`, skills).

## 2. Рекомендуемая форма (для обсуждения)

**Skill `mp-new-product` + YAML per SKU + отчёты в `apps/mp-pipeline/`**.

Почему именно так:
- Паттерн уже проверен на авито (`apps/avito-ads/` + skill `avito-feed-pipeline`).
- YAML = источник правды, легко ревизировать, версионировать в git.
- Skill проводит через 7 фаз с гейтами — как курс, но с принудительными чек-листами.
- Без лишнего: ни веб-дашборда, ни SSR-бэкенда; всё на файлах + Claude Code + ручные API-вызовы.

**Альтернативы, которые я отверг:**
- ❌ Веб-приложение `apps/mp-dashboard/`: сложно, долго, не нужно пока SKU <10.
- ❌ Только markdown-методичка: не даёт структурированного состояния.
- ❌ Convex-бэкенд: оверкилл — нет multi-user, нет real-time.

Каждая фаза:
- Имеет **вход** (что нужно иметь) и **выход** (артефакт: JSON/MD).
- Имеет **чек-лист** (Claude не даёт идти дальше пока не закрыт).
- Имеет **гейт** — явный go/no-go с Антоном.
- Сохраняет прогресс в `apps/mp-pipeline/products/<sku>/state.json` (паттерн `pipeline-state.md`).

## 5. Skill: что делает `/mp-new-product`

- `/mp-new-product new <slug>` — создаёт папку, state.json, brief.yaml → фаза 1.
- `/mp-new-product status <slug>` или без аргументов — отчёт по всем SKU: какая фаза, что блокирует, где гейт.
- `/mp-new-product advance <slug>` — переход на следующую фазу (если чек-лист закрыт).
- `/mp-new-product calc <slug>` — прогон `calc-unit-economics.py`, показ отчёта.
- `/mp-new-product pull <slug>` — пулл продаж из WB/Ozon API (после запуска).

Skill сам по себе — markdown-методичка в `.claude/skills/mp-new-product/` с инструкциями Claude по каждой фазе (как курс, но в коротком виде + явные проверки).

## 6. Что нужно на старте (MVP, минимум)

1. Таблицы комиссий `wb-2026-04.yaml` и `ozon-2026-04.yaml` — спарсить из seller-справочников.
2. `calc-unit-economics.py` — один Python-скрипт, принимает YAML с SKU, выдаёт отчёт.
3. Шаблоны `brief.yaml.tmpl` и `unit-economics.yaml.tmpl`.
4. Skill `/mp-new-product` с 3 подкомандами: `new`, `status`, `calc`.
5. Один тестовый SKU в `products/` — проверяем на реальной идее.

API и прочую автоматизацию **добавляем после** MVP, когда будет 1–2 реальных запуска.

## 7. Где инструмент **не** помогает (границы)

- ❌ Не ищет товар за Антона — нужен ручной клик в MPSTATS/1688 (пока нет ключей сервисов).
- ❌ Не выписывает декларацию соответствия — это сторонняя лаборатория.
- ❌ Не ведёт переговоры с фабрикой — только даёт скрипт.
- ❌ Не запускает РК — только шаблонирует план и бюджеты.
- ❌ Не делает инфографику — даёт ТЗ для дизайнера.
