# Чек-лист методологии «Конвейер новинок»

Что курс **дословно** требует от выбора товара и **как именно** мы это проверяем через MPStats API в фазе MARKET. Источник правды — `course/01-methodology.md` и `course/02-product-search.md`. Где курс не даёт числа — указан **проектный порог** с явной пометкой.

## Уровень SKU — проверяется по каждому кандидату

| # | Курсовой критерий | Цитата | Проверка в API | Порог |
|---|---|---|---|---|
| 1 | Категория из списка курса | «дом и сад, строительство, бытовая техника, автотовары, спорт, зоотовары, хобби» | `path` в `POST /wb/get/category` | стартуем строго из этого списка |
| 2 | Фильтр выручки | «100–300 тыс. руб. при бюджете 150К» | `filterModel.revenue inRange` (синтаксис AG-Grid: `filterType: number, type: inRange, filter, filterTo`) | **100К–300К буквально по курсу** (Вариант А). Масштабирование под другой бюджет курс не даёт |
| 3 | Сортировка по новизне | «от самых новых к старым (по SKU)» | `sortModel: [{colId: "sku_first_date", sort: "desc"}]` | — |
| 4 | Маленькое число отзывов | «маленьким количеством отзывов» | поле `comments` | **проектный под Q2 2026: ≤30** (жёсткий ≤20). Старое значение `≤100` слишком мягко — см. `updates/best-practices-2026/` §10.3 |
| 5 | Остатки быстро тают | «стремительно тающие по остаткам» | `turnover_days`, `sales_per_day_average`, `balance` | **проектные**: `turnover ≤ 60` дн, `sales/d ≥ 0.5`, `not (balance > 200 AND turnover > 30)` |
| 6 | Свежесть карточки | «недавно заведённые карточки» | `days_in_site` | **проектный под Q2 2026: ≤14 дн (Newbie-Boost 3.0)**; `≤180` — для ретро-просмотра товаров вне инкубатора, см. `updates/best-practices-2026/` §10.1 |
| 7 | Окно расчёта потенциала | «за 30 дней продаж» | `d1 = today − 30, d2 = today` | 30 дн (курс) |
| 8 | Потенциал карточки | «текущая выручка + упущенная. ~400К/мес для бюджета 150К» | `revenue_potential` (или `revenue + lost_profit`) | **400К буквально по курсу**; масштабирование под бюджет — открытый вопрос |
| 9 | Чистота карточки без склейки | «товар на Озон должен быть без «склейки»» | косвенно: `start_price/final_price` (>5× — подозрение на болванку); `size_count > 3` — склейка по размерам; **`color_count` API не отдаёт** | финал — ручная проверка по `url` карточки в WB UI (курсовой канон, `02-product-search.md`). Автоматизация через Chrome DevTools MCP — opt-in, оправдана при ≥30 кандидатах в цикле; публичный `card.wb.ru` через прокси режется антифродом (`state:0`) |

## Уровень ниши — kill-критерий, проверяется до отбора SKU

| # | Курсовой критерий | Проверка | Порог |
|---|---|---|---|
| 10 | Распределение Top-1 / Top-20 | `POST /wb/get/category` без `filterModel`, `endRow: 20`, `sort: revenue desc` | `revenue[0]/revenue[19] ≤ 10×` **И** `revenue[19] ≥ 200К` ₽/мес |

Если по нише оба условия не выполнены — **в нишу не идём** (kill по `phases.md` фаза 2 MARKET).

## Чего курс **не требует** для выбора товара

- **Тренд ниши за 6 месяцев** — фигурирует в `phases.md` и `mpstats-api-catalog.md`, но **в курсовых файлах** (`01-methodology.md`, `02-product-search.md`) такой формулировки нет. Это проектное расширение.
- **«Популярность» как фильтр** — курс упоминает популярность только в пункте «Алгоритмы ранжирования» (для продвижения уже запущенного товара, 10–15% веса), не в выборе кандидата. В выборе сигнал популярности косвенно входит через критерий 5 (остатки тают) и критерий 8 (потенциал).
- **Конкретные числовые пороги** для критериев 4, 5, 6 — курс даёт качественные формулировки, числа выше — наша проектная интерпретация под Q2 2026.

## Что добавилось/сместилось в Q2 2026

Эти моменты курс не покрывает, но они влияют на отбор кандидатов:

- **Newbie-Boost 3.0 = 14 дней** — окно «настоящей новинки» сместилось с «недавно» (180 дней в `phases.md`) на 14 дней. Подражание свежему конкуренту имеет смысл только в этом окне.
- **Веса ранжирования сместились**: скорость доставки 30–40%, реклама 15–30%, отзывы упали до 5–10%. Региональная распределённость складов важнее количества отзывов.
- **Микрониши вместо корневых категорий** — курсовые «дом / сад / авто / спорт / строительство» как корни ОК, но дальше искать subject-уровень с low-supply (топ-3 продавца < 80% выручки). Источник: A3 Agency, апр. 2026.
- **Китайские селлеры на WB напрямую с апр. 2026** — фаза SUPPLIER должна проверять, не зарегистрирован ли поставщик уже как продавец WB. При риске — уникализация (комплект, цвет, упаковка).

Подробности с цитатами и источниками — в [updates/best-practices-2026 §10](../../updates/best-practices/).

## Связь с фазами

Чек-лист — операционализация фазы 2 MARKET. Pass всех критериев SKU **+** критерия #10 ниши = можно идти в фазу 3 SUPPLIER. Любой fail на критерии #10 = **kill**, не идём в SUPPLIER даже если SKU красивые.

## Известные пробелы API

- Нет прямого `color_count` от MPStats. Финальная проверка склейки — ручная, по `url` карточки в WB.
- Нет дешёвого способа быстро проверить «нишу не закрыли крупные бренды» — это ручной взгляд на топ-3 в `url`-карточках.
