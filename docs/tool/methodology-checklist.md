# Чек-лист методологии «Конвейер новинок»

Что курс **дословно** требует от выбора товара и **как именно** мы это проверяем через MPStats API в фазе РЫНОК. Источник правды — `course/01-methodology.md` и `course/02-product-search.md`. Где курс не даёт числа — указан **проектный порог** с явной пометкой.

## Уровень артикула — проверяется по каждому кандидату

| # | Курсовой критерий | Цитата | Проверка в API | Порог |
|---|---|---|---|---|
| 1 | Категория из списка курса | «дом и сад, строительство, бытовая техника, автотовары, спорт, товары для животных, хобби» | `path` в `POST /wb/get/category` | Стартуем строго из этого списка |
| 2 | Фильтр выручки | «100–300 тыс. руб. при бюджете 150 тыс.» | `filterModel.revenue inRange` (синтаксис AG-Grid: `filterType: number, type: inRange, filter, filterTo`) | **Параметризация под II квартал 2026:** `min = 1,1 × бюджет, max = 2,9 × бюджет`. Курсовое 100–300 тыс. — Вариант А, годен только для бюджета 150 тыс. Под бюджет 700 тыс. – 1 млн: `[800 000, 2 900 000]`. См. `updates/best-practices-2026/` §10.9 |
| 3 | Сортировка по новизне | «от самых новых к старым (по артикулу)» | `sortModel: [{colId: "sku_first_date", sort: "desc"}]` | — |
| 4 | Маленькое число отзывов | «маленьким количеством отзывов» | Поле `comments` | **Проектный под II квартал 2026: не больше 30** (жёсткий не больше 20). Старое значение «не больше 100» слишком мягко — см. `updates/best-practices-2026/` §10.3 |
| 5 | Остатки быстро тают | «стремительно тающие по остаткам» | `turnover_days`, `sales_per_day_average`, `balance` | **Отбраковочный:** `turnover ≤ 60` дн, `sales/d ≥ 0,5`, `not (balance > 200 AND turnover > 30)`. **Активная гипотеза (§10.11):** `sales/d` зелёная зона 3–10; зона 1–3 допустима только в окне бонуса для новичков (`days_in_site ≤ 14`); больше 20 — вне диапазона бюджета до 1 млн |
| 6 | Свежесть карточки | «недавно созданные карточки» | `days_in_site` | **Проектный под II квартал 2026: не больше 14 дней (бонус для новичков 3.0)**; не больше 180 — для ретро-просмотра товаров вне инкубатора, см. `updates/best-practices-2026/` §10.1 |
| 7 | Окно расчёта потенциала | «за 30 дней продаж» | `d1 = today − 30, d2 = today` | 30 дней (курс) |
| 8 | Потенциал карточки | «текущая выручка + упущенная. ~400 тыс./мес для бюджета 150 тыс.» | `revenue_potential` (или `revenue + lost_profit`) | **400 тыс. буквально по курсу;** масштабирование под бюджет — открытый вопрос |
| 9 | Чистота карточки без склейки | «товар на Ozon должен быть без склейки» | Косвенно: `start_price/final_price` (больше 5× — подозрение на товар-«заменитель»); `size_count > 3` — склейка по размерам; **`color_count` API не отдаёт** | Финал — ручная проверка по `url` карточки в интерфейсе WB (курсовой канон, `02-product-search.md`). Автоматизация через Chrome DevTools MCP — по выбору, оправдана при 30+ кандидатах в цикле; публичный `card.wb.ru` через прокси режется защитой от мошенничества (`state:0`) |

## Уровень ниши — критерий стопа, проверяется до отбора артикулов

| # | Курсовой критерий | Проверка | Порог |
|---|---|---|---|
| 10 | Распределение топ-1 / топ-20 | `POST /wb/get/category` без `filterModel`, `endRow: 20`, `sort: revenue desc` | `revenue[0]/revenue[19] ≤ 10×` **и** `revenue[19] ≥ 200 тыс.` ₽/мес |

Если по нише оба условия не выполнены — **в нишу не идём** (стоп по `phases.md` фаза 2 РЫНОК).

## Чего курс **не требует** для выбора товара

- **Тренд ниши за 6 месяцев** — упоминается в `phases.md` и `mpstats-api-catalog.md`, но **в курсовых файлах** (`01-methodology.md`, `02-product-search.md`) такой формулировки нет. Это проектное расширение.
- **«Популярность» как фильтр** — курс упоминает популярность только в пункте «Алгоритмы ранжирования» (для продвижения уже запущенного товара, 10–15% веса), не в выборе кандидата. В выборе сигнал популярности косвенно входит через критерий 5 (остатки тают) и критерий 8 (потенциал).
- **Конкретные числовые пороги** для критериев 4, 5, 6 — курс даёт качественные формулировки, числа выше — наша проектная интерпретация под II квартал 2026.

## Что добавилось и сместилось во II квартале 2026

Эти моменты курс не покрывает, но они влияют на отбор кандидатов:

- **Бонус для новичков 3.0 — 14 дней.** Окно «настоящей новинки» сместилось с «недавно» (180 дней в `phases.md`) на 14 дней. Подражание свежему конкуренту имеет смысл только в этом окне.
- **Веса ранжирования сместились:** скорость доставки 30–40%, реклама 15–30%, отзывы упали до 5–10%. Региональная распределённость складов важнее количества отзывов.
- **Микро-ниши вместо корневых категорий** — курсовые «дом / сад / авто / спорт / строительство» как корни в порядке, но дальше искать уровень предмета с малым предложением (топ-3 продавцов меньше 80% выручки). Источник: A3 Agency, апрель 2026.
- **Китайские продавцы на WB напрямую с апреля 2026** — фаза «Поставщик» должна проверять, не зарегистрирован ли поставщик уже как продавец WB. При риске — уникализация (комплект, цвет, упаковка).

## Связь с фазами

Чек-лист — операционализация фазы 2 РЫНОК. Прохождение всех критериев артикула **+** критерия №10 ниши = можно идти в фазу 3 ПОСТАВЩИК. Любой провал на критерии №10 = **СТОП**, не идём в ПОСТАВЩИК даже если артикулы красивые.

## Известные пробелы API

- Нет прямого `color_count` от MPStats. Финальная проверка склейки — ручная, по `url` карточки в WB.
- Нет дешёвого способа быстро проверить «нишу не закрыли крупные бренды» — это ручной взгляд на топ-3 в ссылках на карточки.
