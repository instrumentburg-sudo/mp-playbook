# Принятые решения

Живой документ. Каждое решение — дата + обоснование + последствия. Пересматривается при изменении условий.

## 23.04.2026 — базовые вводные проекта

### R1. Профиль оператора
- **Решение:** опытные продавцы, оборот не меньше 5 млн ₽/мес, ищут более прибыльные ниши.
- **Последствия:**
  - Инструмент не «обучающий», а **отсеивающий** — фильтрует товары по цифрам.
  - Главная контрольная точка — юнит-экономика; товары с маржой ниже порога отбраковываются до закупки.
  - Шаги «создать аккаунт продавца», «зарегистрировать ИП» — **не** в круге работы инструмента.

### R2. Площадки
- **Решение:** обе — Wildberries и Ozon.
- **Последствия:**
  - Шаблоны и калькуляторы поддерживают обе сетки комиссий.
  - Для каждого артикула на этапе «Запуск» — отдельный план для WB и Ozon, потому что конкуренция и доля рекламных расходов различаются.
  - Ozon учитывается по тарифам с 06.04.2026 (комиссия до 55% в ряде категорий).

### R3. Категории
- **Решение:** категория **любая**, где сходятся цифры по марже, годовому обороту капитала и по методологии курса.
- **Последствия:**
  - Нет жёсткой привязки к «инструментам / расходникам».
  - Нужна полная таблица комиссий WB и Ozon (по всем категориям) — `commissions/*.yaml`.
  - Фильтр категорий по входному бюджету и целевой марже — в `calc-niche-potential.py`.

### R4. Бюджет на артикул
- **Решение:** до **1 млн ₽ на артикул**, возможно больше.
- **Последствия:**
  - Фильтр MPStats по выручке конкурентов: 600 000 – 3 000 000 ₽/мес (вместо 100–300 тыс. из курса под бюджет 150 тыс.).
  - Партия с 1688: способна тянуть минимальные партии (MOQ) больших фабрик (~500–1 000 штук).
  - Логистика: имеет смысл рассматривать авиа для быстрых циклов на премиум-нишах.

### R5. API
- **Решение:** подключаем **сразу в стартовой версии:**
  - MPStats API (оплачивается отдельно, тариф Advanced / Premium).
  - WB Content / Statistics / Analytics / Promotion API — бесплатно, из своего личного кабинета.
  - Ozon Seller API + Performance API — бесплатно, из своего личного кабинета.
- **Последствия:**
  - Секреты (API-ключи) живут в `~/.config/instrumentburg/api-keys.env` (паттерн проекта).
  - Скрипты на Python + `httpx`, типизация через `dataclasses`.
  - Лимиты запросов учитываются жёстко (ограничение скорости + постоянное кэширование).

### R6. Налоговый режим продавца
- **Решение** (23.04.2026): **УСН 6% «Доходы», без НДС** — стартовая настройка калькулятора.
- **В калькуляторе:** параметр `vat` переключаемый (`0` / `5` без вычетов / `7` с вычетами) — если налоговый профиль изменится, не переписываем код.
- **Напоминание о риске:** при годовой выручке свыше 20 млн ₽ и отсутствии НДС продавец по правилам 2026 может получить требование от налоговой. Отвечает продавец — инструмент только считает и предупреждает, если суммарная выручка перешагнула порог.

### R7. Форма инструмента
- **Решение:** помощник `/mp-new-product` + YAML на артикул + папка `apps/mp-pipeline/` в репозитории `instrumentburg`. Сопутствующая методичка — отдельный публичный репозиторий `mp-playbook` на GitHub Pages.
- **Отклонено:** веб-приложение (`apps/mp-dashboard/`) — избыточно на старте.

### R8. Репозиторий методички
- **Решение:** новый публичный репозиторий `instrumentburg-sudo/mp-playbook`, тема MkDocs Material, публикация через GitHub Actions на `gh-pages`. Адрес: `https://instrumentburg-sudo.github.io/mp-playbook/`.
- **Обоснование:** Антон хочет использовать отдельно от основного проекта.

### R10. Что **не** в круге работы сейчас
- Дизайн инфографики — делает существующий дизайнер по техническому заданию.
- Автоматическое создание карточек в WB / Ozon через API — на втором шаге, после обкатки.
- CRM клиентов, складской учёт, маркировка — есть отдельные инструменты.
- Автоматические самовыкупы, товары-«заменители», раздачи с возвратом денег вне официальных механик — **запрещены** в 2026, не делаем.

### R11. Текущие категории (фильтр против самоканнибализации)
- **Решение:** не предлагать для запуска как «новинку» то, где продавец уже присутствует:
  - Строительный инструмент (перфораторы, шуруповёрты, дрели, болгарки, лобзики).
  - Наборы инструмента (кейсы, ящики, наборы инструмента в чемоданах).
  - Ручной инструмент (отвёртки, молотки, пассатижи, плоскогубцы, стамески, напильники).
  - Автоинструмент (съёмники, динамометрические ключи, наборы для технического обслуживания).
- **Последствия:**
  - В скрипте `calc-niche-potential.py` — список `excluded_domains.yaml` с категориями MPStats и ключами для исключения из выдачи.
  - На фазе «Идея» Claude должен напомнить: «эта идея близка к текущему ассортименту, возможна конкуренция со своим товаром».
- **Где искать:** смежные и дальние ниши с потенциально более высокой маржой — сад / огород, бытовой и хобби-инструмент, расходники / оснастка, мастерская (пайка, электроника, реставрация), автоаксессуары (не инструменты), и непрофильные с высокой маржой.

### R12. Оператор конвейера
- **Решение:** **сам Антон**. Интерфейс должен быть компактным, без бытовых разжёвываний. Чек-листы — только ключевые, не «академические».

### R13. Тариф MPStats
- **Решение:** тариф выбирается **под задачи**: нужен API, инструмент работы с поисковыми запросами, аналитика по категориям. Кандидаты — **Advanced Jam** (минимум для API) или **Premium Jam** (расширенные лимиты, больше сбора данных). Конкретный пакет уточняется у менеджера MPStats после первого прогона конвейера, когда понятны реальные лимиты по запросам.

### R14. Секреты API
- **Решение:** хранить в существующем `~/.config/instrumentburg/api-keys.env` (паттерн проекта). Новые ключи:
  - `WB_API_TOKEN`
  - `OZON_CLIENT_ID`, `OZON_API_KEY`
  - `OZON_PERFORMANCE_CLIENT_ID`, `OZON_PERFORMANCE_CLIENT_SECRET`
  - `MPSTATS_API_TOKEN`

### R15. Вынос в веб-проект
- **Решение:** текущая стартовая версия — помощник + YAML + Python-скрипты в `apps/mp-pipeline/`. Отдельный веб-проект — на **втором шаге**, после 1–2 реальных запусков. До этого не строим.
