# Принятые решения

Живой документ. Каждое решение — дата + обоснование + последствия. Пересматривается при изменении условий.

## 23.04.2026 — базовые вводные проекта

### R1. Профиль оператора
- **Решение**: опытные селлеры, оборот ≥5 млн ₽/мес, ищут маржинальные ниши.
- **Последствия**:
  - Инструмент не «обучающий», а **скрининговый** — фильтрует товары по цифрам.
  - Главный гейт — юнит-экономика; товары с маржой ниже порога отбраковываются до закупки.
  - Шаги «создать аккаунт селлера», «зарегистрировать ИП» — **не** в scope.

### R2. Площадки
- **Решение**: обе — Wildberries и Ozon.
- **Последствия**:
  - Шаблоны и калькуляторы поддерживают обе комиссионные сетки.
  - Для каждого SKU на этапе LAUNCH — отдельный план для WB и Ozon, т.к. конкуренция и ДРР различаются.
  - Ozon учитывается по тарифам с 06.04.2026 (комиссия до 55% в ряде категорий).

### R3. Категории
- **Решение**: категория **любая**, где сходятся цифры по маржинальности, годовому обороту капитала и по методологии курса.
- **Последствия**:
  - Нет хардкода под «инструменты/расходку».
  - Нужна полная таблица комиссий WB и Ozon (по всем категориям) — `commissions/*.yaml`.
  - Фильтр категорий по входному бюджету и целевой марже — в `calc-niche-potential.py`.

### R4. Бюджет на SKU
- **Решение**: до **1 млн ₽ на SKU**, возможно больше.
- **Последствия**:
  - MPSTATS-фильтр по выручке конкурентов: 600 000 – 3 000 000 ₽/мес (вместо 100–300 тыс из курса под бюджет 150k).
  - Партия 1688: способна тянуть минимальные MOQ больших фабрик (~500–1 000 шт).
  - Логистика: имеет смысл рассматривать авиа для быстрых циклов на премиум-нишах.

### R5. API
- **Решение**: подключаем **сразу в MVP**:
  - MPStats API (оплачивается отдельно, тариф Advanced/Premium).
  - WB Content/Statistics/Analytics/Promotion API — бесплатно, из своего ЛК.
  - Ozon Seller API + Performance API — бесплатно, из своего ЛК.
- **Последствия**:
  - Секреты (API-ключи) живут в `~/.config/instrumentburg/api-keys.env` (паттерн проекта).
  - Скрипты на Python + `httpx`, типизация через `dataclasses`.
  - Rate limits учитываются жёстко (throttling + persistent cache).

### R6. Налоговый режим селлера
- **Решение** (23.04.2026): **УСН 6% «Доходы», без НДС** — стартовая настройка калькулятора.
- **В калькуляторе**: параметр `vat` переключаемый (`0` / `5` без вычетов / `7` с вычетами) — если ФНС-профиль изменится, не переписываем код.
- **Риск-напоминание**: при годовой выручке >20 млн ₽ и отсутствии НДС селлер по правилам 2026 может получить требование от ФНС. Отвечает селлер — инструмент только считает и предупреждает, если суммарная выручка перешагнула порог.

### R7. Форма инструмента
- **Решение**: skill `/mp-new-product` + YAML на SKU + папка `apps/mp-pipeline/` в репо `instrumentburg`. Сопутствующая методичка — отдельный публичный репо `mp-playbook` на GitHub Pages.
- **Отклонено**: веб-приложение (`apps/mp-dashboard/`) — оверкилл на старте.

### R8. Репо методички
- **Решение**: новый публичный репо `instrumentburg-sudo/mp-playbook`, тема MkDocs Material, деплой через GitHub Actions на `gh-pages`. URL: `https://instrumentburg-sudo.github.io/mp-playbook/`.
- **Обоснование**: Антон хочет использовать отдельно от основного проекта.

### R9. Что в scope сейчас
- [x] Извлечение курса в markdown.
- [x] Обогащение свежими данными 2026.
- [x] Методичка в MkDocs + GH Pages.
- [ ] Шаблоны комиссий WB и Ozon в YAML (заполнить вручную из таблиц seller-кабинетов).
- [ ] `calc-unit-economics.py` — скрипт юнит-экономики с подключаемыми таблицами.

- [ ] Тестовый SKU для прогона пайплайна.

### R10. Что **не** в scope сейчас
- Дизайн инфографики — делает существующий дизайнер по ТЗ.
- Автогенерация карточек в WB/Ozon через API — на втором шаге, после обкатки.
- CRM клиентов, складской учёт, маркировка — есть отдельные инструменты.
- Автоматические самовыкупы, болванки, кэшбэк-раздачи вне официальных механик — **запрещены** в 2026, не делаем.

### R11. Текущие категории (анти-фильтр скрининга)
- **Решение**: не предлагать для запуска как «новинку» то, где селлер уже присутствует:
  - Строительный инструмент (перфораторы, шуруповёрты, дрели, болгарки, лобзики)
  - Наборы инструмента (кейсы, ящики, head-наборы)
  - Ручной инструмент (отвёртки, молотки, пассатижи, плоскогубцы, стамески, напильники)
  - Автоинструмент (съёмники, динамометрические ключи, наборы для ТО)
- **Последствия**:
  - В скрипте `calc-niche-potential.py` — список `excluded_domains.yaml` с MPStats-категориями и ключами для исключения из выдачи.
  - На фазе IDEA Claude должен напомнить: «эта идея близка к текущему ассортименту, возможна самоканнибализация».
- **Где искать**: смежные и дальние ниши с потенциально более высокой маржой — сад/огород, бытовой/хобби-инструмент, расходка/оснастка, мастерская (пайка, электроника, реставрация), авто-аксессуары (не инструменты), и непрофильные высокомаржинальные.

### R12. Оператор пайплайна
- **Решение**: **сам Антон**. Интерфейс должен быть компактным, без бытовых разжёвываний. Чек-листы — только ключевые, не «академические».

### R13. Тариф MPStats
- **Решение**: тариф выбирается **под задачи**: нужен API, SEO-инструмент, аналитика по категориям. Кандидаты — **Advanced Jam** (минимум для API) или **Premium Jam** (расширенные лимиты, больше скрапинга). Конкретный пакет уточняется у менеджера MPStats после первого прогона пайплайна, когда понятны реальные лимиты по запросам.

### R14. Секреты API
- **Решение**: хранить в существующем `~/.config/instrumentburg/api-keys.env` (паттерн проекта). Новые ключи:
  - `WB_API_TOKEN`
  - `OZON_CLIENT_ID`, `OZON_API_KEY`
  - `OZON_PERFORMANCE_CLIENT_ID`, `OZON_PERFORMANCE_CLIENT_SECRET`
  - `MPSTATS_API_TOKEN`

### R15. Вынос в веб-проект
- **Решение**: текущий MVP — skill + YAML + Python-скрипты в `apps/mp-pipeline/`. Отдельный веб-проект — на **втором шаге**, после 1–2 реальных запусков. До этого — не строим.
